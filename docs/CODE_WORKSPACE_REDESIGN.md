# Code Workspace

How the bot code workspace works now (main brain). Superseded designs and finished Sonnet prompts were removed on 2026-10-03; git history has them. One part is decided but not built: section 7 (toolbar overflow and phones, prompt W7).

Design conventions live in the `botfight-ui-design` skill.

## 0. The lanes editor (current)

Players edit lanes brains (`bot-logic-lanes-v1`, spec in [`LANES.md`](LANES.md)) in one vertical list with no canvas:

- **Sections (mockup section 1):** Movement (the top Move and the top Face card run), Actions (one at a time: the top card that can act; combos indented under their parent), Variables (every card that applies runs). Each section is a coloured label and one muted rule line, no box; Variables shows only its label and "+" while empty. Tiles are coloured by action kind, not by section: Move cyan, Face violet, Ability amber, Dash teal, Cancel red, Variable pink. Phones stack the same way.
- **Layout:** one mode shows no tabs. A quiet "+ Mode" at the top right creates "Mode N" at once and selects it; with two or more modes the tabs appear (the first says Start, "All modes" holds shared switches). Rename by double-click or the tab's ⋯ menu (Rename, Move left/right, Delete; deleting a mode that switches lead to asks first and removes those switches). Each mode shows its switches ("Leave this mode when…"), then the lanes Move, Face, Ability, Dash, Cancel and Variables: coloured labels with no boxes, all shown. An empty lane is its label with a small "+"; "+ Card" is a quiet line under a lane with cards. Shared cards sit under each lane, under an "All modes" divider.
- **Cards** are one row (`LaneCardRow.jsx`, mockup section 1): the priority number (top-level cards only), the action tile (a chevron in the action's kind colour, with the ability's artwork or a small inline icon from `laneIcons.jsx`), the condition tiles (icon, short name, value in yellow, from `conditionCatalog.js`), and a dashed "+ Condition". The ⋯ menu shows on hover (always on touch and phones) and holds Add follow-up (ability and dash cards), Add movement while casting (ability cards), Move to All modes or Move to this mode (with two or more modes; top-level cards only), Duplicate, Move up and down, Turn off or on, and Delete. A follow-up is indented under its parent with a left line and no number. An ability card's attached movement (a move or face action set by "Add movement while casting") sits after its ability tile as smaller tiles joined by "＋"; clicking one opens its own editor, which says Remove instead of Delete card. A condition tile opens a one-line editor under the row (comparator, number or "Num | reading", or a yes-or-no toggle; Remove), and Esc or the tile closes it. Sentences (`laneSentence.js`) leave out "My Bot" and name abilities. Clicking the action tile opens the action editor under the row (below).
- **Card menu:** "+ Card" in a lane, `/` (outside a text field: the selected card's lane, else the Ability lane) and "Add follow-up" open one menu under their button (`LaneCardMenu.jsx`; the shell is `LaneMenuShell.jsx`, the list model `cardMenu.js` and `menuModel.js`). "+ Card" lists the lane's actions (the Ability lane shows the loadout as icon tiles) and below them the ready-made cards for that lane (`quickAdd.js`: each action with default settings, with no condition and with each of: distance within the ability's base range, my HP below 30%, an enemy winding up, the ability ready). "Add follow-up" shows the Actions choices (abilities, dash, cancel); "Add movement while casting" shows the move and face actions and sets the card's attached move or face. Abilities are icon tiles with an ⓘ that opens the details panel (`AbilityDetailsPopover.jsx`: one line of description and only the stats the ability has, from the gameplay data, read-only; a bottom sheet under 600 px). The footer shows the highlighted action's stats. Typed words must start a word of a name or description, case-insensitive; ↑ ↓ move, Enter adds.
- **Swap ("Change" in the action editor):** the same menu lists only the actions that fit the card (`laneEdits.actionFitsCard`). A top-level card keeps its lane. A card with follow-ups keeps them only for an ability or dash action, so a plain action is refused with a message; follow-ups are never dropped to make room. The card keeps its conditions, except ability readings of the old ability, which follow the new ability or are removed (the board shows how many).
- **Condition menu:** "+ Condition" opens it under its button (`LaneConditionMenu.jsx`, groups in `conditionMenu.js`): a rail of groups with counts (an empty group fades) and one list with sticky headers, each item an icon, a short name and a muted description. Groups: Me, Enemy, the card's ability (named after it), Other abilities (each other loadout ability's Ready, Winding up and Hit recently, named "Fireball: Ready"), Objects, Match, Variables (the brain's custom variables, with type and current value; when there are none, "No variables yet" and a link to the Variables dialog). Typing filters live and highlights the first match. Picking adds the condition through its catalog build and opens its editor.
- **Action editor:** clicking the action tile opens one line under the row (`LaneActionEditor.jsx`, fields from `actionEditorModel.js`): the action's name and "Change", then Target as a segmented control with only the targets the action supports (Enemy, Point, Angle; Point and Angle show number boxes), then its own settings (Walk: Direction Toward, Strafe or Away, and Sprint; Face: Fast turn; ability Aim Current, Lead or Auto, with Auto leading by the wind-up left plus the travel time; Face Aim Current, Lead or Auto, where Auto picks a loadout projectile ability (a Face attached to a projectile card starts on Auto with it); a new projectile ability that aims at an entity starts on Auto, `aimDefaults.js`; an ⓘ after the name opens the details panel; a variable card's value), and "Delete card" on the right. The settings come from the same contract fields the old side panel read. Tile labels: "Walk to enemy", "Face enemy", "Cancel wind-up"; an ability shows its name. Ability artwork sits on a dark square with a lane-coloured border.
- **Menus:** the shell renders into `document.body`, so no workspace scroll container clips it. On a desktop it is 300 px tall under its button, shifted left to stay on the screen and placed above the button when there is no room below. Under 600 px it is a bottom sheet above the phone bar, with the rail as a sideways-scrolling chip row and the list filling the rest. The search row has no box of its own and is focused on open. Esc closes; a press outside closes; the button itself toggles.
- **Live highlight (practice room only, while a preview runs):** the current mode's tab has a ring with its time in mode, and every card that acted this tick (its move, face, action or variable card) gets a 3 px left bar in its kind colour. A running combo step keeps its bar while its action runs, and its parents get a faint one (`liveHighlight.js`). Data flows `Arena` (`main`'s frame) → `CodingPanel` `liveLanes` → `LanesBoard` `live`, as ids only (winners and `comboStepId`). Never for an opponent, offline or rated bot.
- **Undo** is the workspace's existing history. Every edit goes through the pure ops in `coding/lanes/laneEdits.js`, which normalize with the engine's lanes normalizer, enforce the lanes limits, and refuse an edit that adds a validation error.
- **New or cleared brains** become the starter (`coding/lanes/laneStarter.js`): one mode "Main" with Move, Face and an Ability card per equipped ability with a base range.
- **Old brains** (tree format) show a notice and cannot be edited. Puzzle and tutorial rooms stay on the tree path: no auto-start, and no "Start a new brain" button in puzzle rooms.
- **Persistence** saves lanes brains as they are. The loadout sanitizer only drops cards whose ability is not equipped.
- **Variables:** rename and delete walk lanes cards and switches (`coding/variableUsage.js`).

Sections 1 to 8 describe the tree editor. It is **legacy and read-only**: the engine still runs tree brains, but the workspace no longer creates or edits them. `LogicBoard.jsx` and the tree node code remain in the repository until the tree runtime is removed.

## 1. Brain format and execution order (legacy, read-only)

- **Legacy:** everything in this section describes the tree format (`bot-logic-tree-v2`). It still runs for existing puzzles, golden scenarios and old saves; the editor no longer edits it (see section 0).
- **Tree:** `roots -> branches (conditionals) -> children / actions`. One movement, rotation, ability and cancel action per tick; variable writes all apply.
- **Order is left to right** (modelled on Unreal's behavior tree editor). Roots are ordered among roots; conditionals that share a parent form an IF / ELSE IF / ELSE chain where the first match wins. ELSE always counts as last. The stored `priority` fields are what the runtime uses; the editor writes them from horizontal positions, and badges update live while dragging. Older brains whose layout disagrees with their stored order keep their order and get an amber ring on the group's badges; dragging applies left-to-right order, Tidy fixes the layout.
- **Actions inside a branch are not ordered:** a matched branch runs all its actions, one per category. A matched child's actions beat its parent's in the same category.
- **Root actions:** an action wired straight to a root (`root.actions`) runs every tick alongside whichever branch matches; a matched branch's action in the same category wins.
- **Orphans:** nodes not connected to a root are saved in `orphans` (an orphan conditional keeps its subtree), never run, count toward the budget, and are validated like connected nodes on both sides. Submitting with orphans warns but does not block.
- **Conditions are AND-only.** OR is a sibling ELSE IF with the same action, which can be shared instead of duplicated (see "Shared actions" below). Old brains with `join: "or"` load as AND; the server rejects any join other than `"and"`. Puzzle outcome conditions are a separate system and still support OR.
- **Shared actions:** an action node can have several parents (conditionals or roots); roots and conditionals still have exactly one. A shared action runs if any path to it matches, and its priority comes from the first matching path, exactly like separate copies. "One action per category per conditional" is checked for each parent. Chains are unchanged.
  - **Storage:** nothing changes for the simulation. The editor shows one node but saves a copy under each parent, all with the same optional `linkId` (1-40 characters of `A-Za-z0-9_-`). Both runtimes run the copies as they always did. On load, copies with the same `linkId` and identical content (everything but their own `id`) merge into one node; if they differ (hand-edited) or a link has a single copy, they load as separate nodes and the `linkId` is dropped. Editing one copy writes the change to the others.
  - **Budget:** identical linked copies count as one action, on the client (`configurationMetrics.js`, `rootNormalizer.js`) and on the server (`BrainNormalizer.java`, `BotSubmissionValidationService.java`, via `LinkedActions.java`). Copies with the same `linkId` but different content count separately.
- **Comparing two pair values** (distance, bearing): each side has its own entities and target (`rightSelectable1`, `rightSelectable2`, `rightTargetMode`, `rightTargetX/Y`, `rightTargetAngle`). Older brains without the right-side fields fall back to the left side's.

## 2. Main brain canvas: nodes, pins and wires

- **Nodes are plain rectangles in a thin frame.** Pins are wide bars flush on the frame edges: input along the top, output along the bottom (about 16 px, hit area ≥ 24 px, ≥ 34 px on touch). Root: output only. Conditional: both. Action: input only.
- **Wires** start exactly on the parent frame's bottom edge and end exactly on the child frame's top edge (bar centres), from measured frame geometry at every zoom (`coding/graphEdgeGeometry.js`).
- **Connecting:**
  - Click an output bar to arm it (a preview wire follows the cursor), then click a valid input bar. Nothing ever connects on hover or pass-over.
  - Or press an output bar and move more than about 4 px: the held wire connects when released over any part of a valid node and drops when released elsewhere.
  - Click empty canvas or press Escape to cancel.
- **Touch:** no wire follows the finger. Tap an output bar to arm it (banner: "Tap an input to connect. Tap empty space to cancel."), then tap the target's input bar. Panning and pinch-zoom keep it armed; a still tap on empty canvas disarms. A press that starts on a pin bar drags a held wire instead of panning.
- **Rules:** roots and conditionals take one wire (wiring a connected one moves it, in either click order); an action takes any number. Wiring an output to an action that already has a parent **adds** a parent (the action becomes shared). An unconnected action just takes its first parent. No cycles. A refused target turns red with the reason as its tooltip ("That would create a loop", "This conditional already has a Move action", "Already connected to this node"), and clicking it shows the reason as a toast. A conditional wired under a parent is inserted by X position (ELSE last).
- **Re-parent:** click a connected conditional's input bar; its wire lifts and follows the cursor. A shared action's input bar lifts nothing; its tooltip and toast say "Connected to N nodes. Select a wire to disconnect it." An action with one parent lifts as before. **Disconnect:** select a wire and press Delete; that wire alone is removed. Removing the last parent makes the action an orphan; a conditional becomes an orphan as before.
- **Shared actions on the canvas:** drawn once, with a wire from each parent. Deleting a shared action removes it from every parent after a confirmation ("This action is used by N branches."). Its side panel has a "Used by" row listing each parent (yellow IF / ELSE IF / ROOT label, then the root's name, styled like "Used in" in the variables dialog); clicking one selects that parent. Tidy places the action under its first (highest-priority) parent and draws the other wires to it. Undo and redo cover adding a parent, removing a parent and deleting.
- **New nodes:** double-click empty canvas or "+ Node" opens the node picker; the node is placed unconnected.
- **Ability not equipped:** an action whose ability isn't in the loadout renders as a muted "Ability not equipped" node that can still be wired, disconnected or deleted.
- **Selecting vs opening:** pressing a node and moving it more than 4 px is a drag and never selects or opens. An action: one tap selects it and opens its panel. A conditional: the first click selects it; once selected, clicking a condition strip opens that condition. Tapping another node closes any open panel; Ctrl/Cmd-click adds to the selection without opening.
- **Order controls:** the side panel header shows "IF, 1 of 3" with ‹ › for keyboard and precise moves.
- **Action node (both editors):** up to three rows: (1) the yellow category label (ABILITY, MOVE…) with the × on the right, (2) the action name on a darker green (`#264a2e`), (3) a description of its settings on the darkest green (`#1c3823`, text `#cfe9c6`), only for actions that have settings. Chains add the step number at the start of row 1.
- **Phones (both editors):** a tap only selects; no sheet opens. While something is selected the bottom bar becomes contextual: Edit (opens the config sheet; a second tap on the selection does the same), Disconnect (main brain; for a shared action it cuts the selected wire), Up, Down, Delete, Done. Done clears the selection and restores the normal bar.

## 3. Conditional node (main brain)

- Light blue body (`#286583`, border `#43a6d1`) with one darker blue strip per condition (`#0d2f50`, border `rgba(125,211,252,.56)`), inside its pin frame.
- Header row: the yellow (`#facc15`) IF / ELSE IF / ELSE label, "all must be true" (two or more conditions), then the action count and order badge on the right.
- Strips: × on each, a white outline when selected, truncated with a full-text tooltip.
- A small dashed "+ Condition" button, sized to its text and left-aligned under the last strip (not a full-width row), adds a strip and opens it (hidden on read-only canvases).

## 4. Side panels (both editors)

On phones the panel is a bottom sheet.

- **Flat rows, no indentation:** label left (muted), control right. Indentation was tried and rejected.
- **Controls are only as wide as their content**, right-aligned, truncating at about 200 px with a tooltip. Numbers are a fixed 5-digit box (about 72 px, monospace) with the unit outside. Segmented controls show only the options that exist, each sized to its text. The ⓘ sits right after its label.
- **Condition:** header (yellow kind label, "Condition 2 of 3", ×); **Value** and its rows (Entity, To, X / Y, Ability, Status…); a hairline, **Compare**, a hairline; **With** (Num | Var); **Value** again (always "Value", never "Number" / "Variable") and, for a variable, its own rows; footer with a quiet red remove.
- **Action:** header (yellow category label, title, ×); **Action**; **Target** (Entity | Point | Angle, only supported modes) and its rows; then the action's own rows (Direction, Sprint, Aim, Continue, For / Until…); footer as above.
- Help text sits behind an ⓘ; comparators may read as words; units follow values.

## 6. Toolbar, dialogs and helpers

- **Toolbar** (`CodingPanel.jsx`, `code-tb-*`): bot switcher (with Sandbox | Real for teammates in live matches), budget meters (amber from 85%, red at the limit), Search roots (`/`), Variables, Add root (the one filled button, with its shortcut), + Node, Clear all (quiet red, one confirmation listing counts, one undo restores everything) and Close. It changes with the workspace's width in three stages (section 7): full, mid (icon-only secondaries and a ⋯ More menu) and phone (identity and budget chips on top, a bottom action bar).
- **Canvas rail and zoom:** undo, redo, Zoom to fit (minimum zoom 25%) and Tidy (sorts every sibling list by execution order and re-runs the layout; recorded in undo). Zoom (−, %, +, fit) floats at the canvas's bottom-right. The canvas is 10,000 × 6,000; large sibling groups are the author's to arrange.
- **Variables dialog** (`CustomVariablesModal.jsx`, `code-cv-*`): header "Variables", a slot meter (bar and mono "3 / 8", amber from 85%, red at the limit) and ×. The list shows each variable's name, a type tag (Number cyan, True/false purple) and its live value in mono; "+ New variable" is the one filled button. Types are Number and True/false only (timers were removed). The detail is compact 32 px rows, label left and control right: Name; Type (Number | True/false); Starts at (a 5-digit box, or False | True); a hairline; Live value; then "Used in N places" with one row per use (yellow kind label such as IF, SET or STEP 4, then the root or chain name and a summary). Clicking a use closes the dialog and selects that node, or opens the chain and selects the step. Uses are found by `coding/variableUsage.js`, which walks roots, unconnected nodes and chains (steps, nested If / Repeat bodies and loose blocks); deleting a variable (after a confirmation when it is used) and changing its type rewrite the same places. A quiet red "Delete variable" sits at the bottom. Phones: list, detail and the uses list are separate screens; the "Used in" row opens the uses list.
- **Movement direction guide** (`AngleGuideDialog.jsx`, `angleGuideMath.js`): one dialog titled "Movement direction" with a Relative | Absolute toggle and ×. The Direction ⓘ on a relative move opens it on Relative; every Angle ⓘ opens it on Absolute. A 300 px SVG arena has a draggable Me (cyan) and Opp (red); Relative draws a dashed line from Me to Opp, Absolute draws an N/E/S/W ring around Me with Opp dimmed. A green arrow shows the heading and a yellow arc shows the angle in degrees. Controls: a 5-digit number box with "deg", preset chips, a one-line caption that changes with the angle, Play / Pause and Reset (a small loop where the bot steers by its direction each frame; it stops at walls, on contact or after 6 s, leaving a dashed trail) and a footnote with the 0° and sign conventions. Under `prefers-reduced-motion` Play shows the finished trail instead of animating. Phones: arena on top, controls below. `PhaseStrikeLandingModal` (Landing rotation) uses the same shell.
- **Search roots popover** (`SearchRootNodesModal.jsx`, `code-rs-*`): anchored under the toolbar button, own search input, rows with order badge, name and counts, footer hints and a quiet red "Delete all roots" while the query is empty. Phones: a full-width sheet.
- **Mobile input zoom:** picker search boxes only autofocus with a fine pointer, and workspace inputs use 16 px text on touch screens so mobile browsers don't zoom.
- **Fonts:** `.testing-mono` forces Cousine across the workspace, so the toolbar, zoom cluster and dialogs opt back into IBM Plex Sans (monospace only for numbers and `kbd`).

## 7. Toolbar overflow and phones (built)

Built 2026-10-04. Three stages (full, mid, phone), decided by the workspace element's width, not the device.

### Mid width (about 640–1100 px)

- One row. Identity left (bot selector), budget as compact chips (R / A / C).
- Search, Variables and + Node become icon-only buttons with tooltips. The primary keeps its label (Add root).
- A **⋯ More** menu holds Tidy layout, Zoom to fit, and Clear all last in quiet red below a divider. Close stays far right.

### Phone (under 640 px)

- **Top:** row 1 is identity, a search icon (main brain only) and Close; row 2 is the budget chips, which open a sheet with full counts and limits.
- **Bottom action bar** (about 52 px, five slots with icon and short label): Undo, Redo, **Add** (the only filled primary, centred), Vars, More.
  - Add opens a sheet listing Add root, Conditional node and Action node….
  - More (sheet): Tidy layout and Zoom to fit, then Clear all in quiet red.
- **Canvas:** no left rail on phones; a small floating cluster at the canvas's bottom-right keeps Zoom to fit, − and +.
- **Layering:** the side panel opens as a bottom sheet covering the bar; the pin banner sits just above the bar.
